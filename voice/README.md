# Saydo Voice — 시리로 할 일 확인·등록

아이폰에서 **앱을 열지 않고** 말로 처리합니다. 잠금화면, 운전 중, 에어팟에서도 됩니다.

```
"시리야, 할 일 추가"
  → "추가할 할 일을 말씀하세요"
  → "내일 오후 3시 배포 파이프라인 점검 급한 걸로"
  → "내일 15시 00분에 우선순위 1로 배포 파이프라인 점검, 프로젝트에 추가했습니다."

"시리야, 오늘 할 일"
  → "오늘 할 일 4건입니다. 긴급, 분기 예산안 검토. …
     기한이 지난 것은 5건이고, 가장 오래된 것은 400일 지난 자기앞의 생 읽기입니다."
```

## 왜 Apps Script 인가

프록시 후보가 차례로 막혔고, Apps Script 만 전부 통과합니다.

| | Cloudflare Workers | Cloud Run (회사) | 맥 로컬 | **Apps Script** |
|---|---|---|---|---|
| Gemini 지역 차단 | ✗ egress IP 거부 | ○ | ○ | **○ Google 인프라에서 나감** |
| 조직 정책 | — | ✗ `allUsers` 금지 | — | **○ 무관** |
| 키 보관 | ○ | ✗ Secret Manager 권한 없음 | ○ | **○ Script Properties** |
| 항상 켜짐 | ○ | ○ | ✗ 맥 의존 | **○** |
| 스크립트 실행·Tasks 접근 | 개인 | 회사(막힘)/개인 | — | **회사 Workspace** |

> **정정(2026-09-01).** 이 표에 원래 "계약·과금 주체 = 회사 Workspace" 라고 적고
> "사내 과제명이 회사 계약 안에서 처리된다" 고 썼는데 **부정확했다.** Workspace 안에
> 있는 것은 *스크립트 실행과 Tasks 접근*뿐이고, `UrlFetchApp` 이
> `generativelanguage.googleapis.com` 으로 나가는 호출은 **API 키가 속한 프로젝트의
> Gemini API 약관·과금**을 따른다. Workspace DPA 가 덮어 주지 않는다.
>
> 개인 사용에서는 감수할 만하다. 다만 **사내로 확산한다면** 회사 GCP 프로젝트의
> **Vertex AI** 로 옮겨야 한다 — 리전 고정, 회사 계약 적용, 감사 로그가 따라온다.

**앱 본체를 Apps Script 로 옮기는 것이 아닙니다.** 앱은 지금처럼 Cloudflare Pages 의
PWA 로 남습니다(홈 화면 설치·오프라인·직접 API 호출이 필요하므로). 음성 백엔드만
Apps Script 입니다. 둘은 같은 `⟦…⟧` 메타 인코딩을 쓰므로 어느 쪽에서 만들어도
서로 읽습니다 — `voicetest.js` 가 이 동일성을 바이트 단위로 검증합니다.

## 보안 모델

```
[아이폰 단축어] ── HTTPS POST { secret, action, text } ──▶ [Apps Script]
                                                              │ 키는 여기에만
                                                              ├─▶ Gemini (파싱)
                                                              └─▶ Tasks API (내 권한)
```

- `GEMINI_API_KEY`, `SHARED_SECRET` 은 **Script Properties** 에만 있습니다. 코드에도
  단축어에도 키 자체는 들어가지 않습니다(단축어에는 시크릿만).
- 모든 요청을 `SHARED_SECRET` 으로 검증합니다. 비교는 **길이 확인 + 전체 XOR** 이라
  앞자리만 맞혀 가며 뚫는 방식이 통하지 않습니다.
- Tasks API 는 `ScriptApp.getOAuthToken()` — **스크립트 소유자(나) 권한**으로만 돕니다.
- `doGet` 은 설정 여부(`hasKey`/`hasSecret`)만 알려주고 값은 절대 돌려주지 않습니다.

**엔드포인트가 공개(`ANYONE_ANONYMOUS`)인 이유** — 시리 단축어는 Google 로그인을
할 수 없습니다. 도메인 제한 배포로는 로그인 화면(HTML)이 돌아와 동작하지 않습니다.
그래서 접근 자체는 열되 **시크릿으로 잠급니다.** 40자 난수를 모르면 아무것도 못 합니다.

> 조직 정책상 `모든 사용자` 배포가 막혀 있으면 이 경로는 성립하지 않습니다.
> 배포 3단계에서 드롭다운에 그 항목이 있는지가 이 설계의 성패를 가릅니다.

### ⚠ 이 백엔드는 1인용이다 — 시크릿을 남에게 주지 말 것

`executeAs: USER_DEPLOYING` + `ScriptApp.getOAuthToken()` 이므로 **누가 부르든 Tasks
호출은 스크립트 소유자 권한으로 돈다.** 시크릿은 사용자 구분이 아니라 문 하나를 여는
열쇠다. 즉 시크릿을 받은 사람이 앱의 AI 어시스턴트로 태스크를 만들면 **소유자의 목록에
생기고**, 조회하면 **소유자의 할 일이 읽힌다.** 앱 본체(PWA)는 각자 OAuth 하므로
멀쩡한데, AI 경로만 이렇게 새는 비대칭이라 눈치채기 어렵다.

여러 명이 쓰려면 **요청 본문에 각자의 액세스 토큰을 실어 보내고** 서버가
`getOAuthToken()` 대신 그 토큰으로 `UrlFetchApp` 을 호출하도록 고쳐야 한다(앱은 이미
GIS 로 그 토큰을 갖고 있다). 그러면 격리가 토큰 단위로 성립하고 시크릿의 역할은
"Gemini 남용 방지"로 축소된다. 도메인 제한 배포(`USER_ACCESSING`)는 답이 아니다 —
브라우저 fetch 에 구글 세션이 실리지 않아 로그인 HTML 이 돌아온다.

시리 단축어는 OAuth 를 못 하므로 이 개조로도 공유되지 않는다. 각자 자기 스크립트를
배포하는 수밖에 없다.

## 앱의 AI 어시스턴트도 여기로 (action=chat)

시리뿐 아니라 **Saydo 앱의 AI 어시스턴트**도 이 백엔드를 씁니다. 그러면 맥 로컬 프록시가
필요 없어지고, 아이폰·아이패드·다른 맥에서 그대로 동작합니다.

**설정** — 앱 사이드바 AI 어시스턴트 → 톱니 → 프록시 주소에 **웹앱 URL**, 그 아래
나타나는 **시크릿** 칸에 40자를 넣고 저장.

**왜 프로토콜이 다른가** — 브라우저에서 Apps Script 를 부르려면 제약이 둘입니다.

- **CORS**: `Authorization` 헤더나 `application/json` 은 preflight(OPTIONS)를 부르는데
  Apps Script 는 OPTIONS 를 처리하지 못합니다. 단순 요청(`text/plain`)만 통과합니다.
- **크기**: 도구 정의 6개와 태스크 스냅샷 전체를 실으면 GET 폴백에서 URL 길이를 넘깁니다.

그래서 **대화 전체를 서버가 처리합니다.** 브라우저는 문장 한 줄만 보내고, 스냅샷 수집·
모델 호출·도구 실행이 전부 여기서 일어납니다. 끝나면 `changed:true` 를 보고 앱이
동기화해 화면을 맞춥니다.

```
[브라우저] "지연 분석해 줘"  ──POST text/plain──▶ [Apps Script]
                                                   ├─ 스냅샷 수집 (Tasks API)
                                                   ├─ Gemini + 도구 6종
                                                   └─ 도구 실행 (Tasks API)
```

POST 본문이 302 리디렉션에서 사라지는 환경이면 앱이 자동으로 **쿼리 방식으로 재시도**합니다
— 시리에서 실제로 겪은 경로라 앱에도 같은 대비를 넣었습니다.

**시크릿이 브라우저에 저장되는 점** — 로컬 프록시 방식은 Google 토큰으로 인증해서
시크릿이 필요 없었습니다. Apps Script 는 CORS 때문에 그 방식을 못 써서 시크릿을
브라우저 저장소에 둡니다. 본인 기기에만 남고, `setupSecret` 으로 언제든 재발급할 수
있지만, 로컬 방식보다 한 단계 약한 것은 사실입니다.

## 설치 (약 15분, 최초 1회)

### 1. 스크립트 만들기

<https://script.google.com> → **새 프로젝트** → 이름 `saydo-voice`

- 왼쪽 `Code.gs` 내용을 전부 지우고 이 폴더의 **`Code.gs`** 를 붙여넣습니다.
- 왼쪽 톱니(**프로젝트 설정**) → **"appsscript.json" 매니페스트 파일 표시** 체크
- 편집기로 돌아가 `appsscript.json` 을 이 폴더의 것으로 교체합니다.

### 2. 비밀값 넣기

**프로젝트 설정 → 스크립트 속성 → 속성 추가**

| 속성 | 값 |
|---|---|
| `GEMINI_API_KEY` | AI Studio 에서 발급한 **유료 티어** 키 (`Gemini API Key-saydo-local` 과 별도로 하나 더 발급 권장) |
| `SHARED_SECRET` | 비워 두고 아래에서 생성 |

편집기에서 함수 `setupSecret` 선택 → **실행** → **실행 로그**에 나온 40자를 복사해 둡니다.
(이미 있으면 덮어쓰지 않습니다. 단축어가 갑자기 죽는 것을 막기 위해서입니다.)

### 3. 권한 승인 + 동작 확인

함수 `checkSetup` 선택 → **실행** → 권한 요청이 뜹니다.
"이 앱은 확인되지 않았습니다" 화면에서 **고급 → saydo-voice(안전하지 않음)으로 이동** —
본인이 방금 만든 스크립트이므로 정상입니다.

실행 로그에 목록 이름들과 오늘 요약이 찍히면 Tasks 연결이 된 것입니다.

### 4. 배포

**배포 → 새 배포 → 유형: 웹 앱**

| 항목 | 값 |
|---|---|
| 실행 계정 | **나** |
| 액세스 권한 | **모든 사용자** ← 이 항목이 없으면 아래 "막혔을 때" 참고 |

배포 후 나오는 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`) 을 복사합니다.

확인:

```bash
curl -sL '<웹앱 URL>'
# {"ok":true,"service":"saydo-voice","hasKey":true,"hasSecret":true}
```

`hasKey` 나 `hasSecret` 이 `false` 면 2단계로 돌아가십시오.

### 5. 단축어 만들기 (아이폰)

**단축어 앱 → + → 새 단축어**

**단축어 A — "할 일 추가"**

1. **입력 요청** — 입력 유형 `텍스트`, **프롬프트에 `추가할 할 일을 말씀하세요`**
   (프롬프트를 비우면 시리가 `"텍스트가 어떻게 됩니까?"` 라는 기본 문구를 씁니다)
2. **URL 콘텐츠 가져오기**
   - URL: 웹 앱 URL
   - 방법: **POST**
   - 요청 본문: **JSON**
     | 키 | 유형 | 값 |
     |---|---|---|
     | `secret` | 텍스트 | (2단계의 40자) |
     | `action` | 텍스트 | `add` |
     | `text` | 텍스트 | *받아쓰기 결과* 변수 |
3. **사전 값 가져오기** — 키 `speak`
4. **텍스트 말하기** — 위 결과

이름을 **"할 일 추가"** 로 저장. 시리에게 "할 일 추가"라고 부르면 실행됩니다.

**단축어 B — "오늘 할 일"**

1단계(입력 요청)를 빼고, `action` 을 `today` 로, `text` 는 넣지 않습니다. 나머지는 동일.

**단축어 C — "타스크" (등록·질문을 한 번에)** ← 권장

`action` 을 **`chat&voice=1`** 로 두면 말한 내용을 서버가 판단합니다. 앱의 AI 어시스턴트와
같은 경로라 태스크 전체를 보고 답하고, 필요하면 직접 만들고 고칩니다.

```
"오늘 할 일 알려줘"  "급한 일 뭐 있어"  "내일 3시 배포 파이프라인 점검 추가"  "이번 주 뭐가 밀렸어"
```

`voice=1` 이 없으면 **화면용 긴 답**이 돌아와 시리가 한참 읽습니다. 이 플래그가 있으면
마크다운 금지·3문장 이내로 답하고, 그래도 길면 문장 경계에서 자릅니다.
대신 스냅샷과 도구 왕복 때문에 `add` 보다 몇 초 느립니다 — 자세한 것은 `SHORTCUT.md`.

> 화면별 상세 안내는 **`SHORTCUT.md`** 에 따로 있습니다. 302 리디렉션에서 POST 본문이
> 유실되는 경우의 우회(쿼리 파라미터 방식)도 거기에 있고, 서버는 두 방식을 모두 받습니다.

## 막혔을 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 배포 드롭다운에 **모든 사용자**가 없음 | Workspace 관리자가 외부 공개 배포를 차단 | 이 경로는 불가. 맥 터널 또는 Cloud Run 예외 요청으로 전환 |
| 단축어가 HTML 을 받아옴 | 도메인 제한으로 배포됨 → 로그인 페이지 | 배포를 **모든 사용자**로 다시 만들기 |
| `인증에 실패했습니다` | 시크릿 불일치 | 단축어의 `secret` 값과 스크립트 속성 대조 (공백 혼입 주의) |
| `Gemini 가 이 서버 위치를 거부` | Apps Script egress 도 차단됨 | 이 설계의 핵심 가정이 깨진 것. Vertex AI 전환 검토 |
| `API 키가 설정되지 않았습니다` | 속성 이름 오타 | `GEMINI_API_KEY` 철자 확인 |
| `Tasks API 가 … 꺼져 있습니다` | 스크립트의 Cloud 프로젝트에서 Tasks API 미활성화 | 편집기 왼쪽 **서비스 +** → **Tasks API** → 추가 |
| 코드를 고쳤는데 반영 안 됨 | 배포는 스냅샷 | **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** (URL 유지) |
| 단축어가 상태 JSON 을 읽어 줌 | 302 에서 POST 본문 유실 | `SHORTCUT.md` 의 쿼리 파라미터 우회 |

## 검증

```bash
node voicetest.js      # 122/122
```

Apps Script 는 로컬 실행이 안 되므로, GAS 전역을 흉내 낸 샌드박스에서 순수 로직만
돌립니다. 검증 범위는 **메타 인코딩이 `core.js` 와 바이트 단위로 같은가**(두 앱이
같은 데이터를 쓰는지), 시크릿 비교, 인증 실패 시 아무 동작도 하지 않는지,
`doGet` 이 비밀값을 흘리지 않는지, 목록 매칭 규칙, 음성 낭독 길이 제한입니다.

네트워크 호출(Gemini·Tasks)은 범위 밖이며 3단계 `checkSetup` 으로 실기 확인합니다.
