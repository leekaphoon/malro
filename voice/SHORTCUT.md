# 아이폰 단축어 만들기 — 처음부터

`voice/README.md` 의 1~4단계(스크립트 배포)를 마친 상태에서 시작합니다.
브라우저에서 웹앱 URL 을 열었을 때 `{"ok":true,"service":"saydo-voice",...}` 가 나와야 합니다.

## 왜 GET 인가 (실측 기록)

처음에는 POST + JSON 본문으로 설계했습니다. **동작하지 않습니다.**

Apps Script 의 `/exec` 는 응답을 `googleusercontent.com` 으로 302 리디렉션합니다.
iOS 단축어는 그 리디렉션을 따라가면서 **요청 본문을 버립니다.** 서버는 빈 요청을 받아
기본 동작으로 해석하고, 시크릿이 없으니 `인증에 실패했습니다` 를 돌려줍니다.

증상이 헷갈리는 이유가 여기 있습니다 — 필드를 아무리 고쳐도 같은 메시지가 나옵니다.
필드가 서버에 도달조차 하지 않기 때문입니다. `action` 을 `debug` 로 바꿔도 인증 실패가
나온다면 그것이 본문 유실의 확증입니다.

**쿼리 문자열은 리디렉션에서 살아남습니다.** 브라우저에서 `?action=debug&secret=…` 이
정상 동작하는 것이 그 증거입니다. 그래서 서버는 GET 쿼리도 POST 본문과 동일하게
처리하도록 만들어져 있습니다.

> 대가: 시크릿이 URL 에 실려 Google 접속 로그에 남습니다. 이 경로가 막힌 이상 현실적인
> 선택이며, 시크릿은 `setupSecret` 으로 언제든 재발급할 수 있습니다.

## 준비물

아이폰에 붙여넣을 수 있게 두 가지를 준비하십시오. 맥에서 복사하면 유니버설 클립보드로
넘어갑니다.

1. **웹앱 URL** — Apps Script → 배포 → **배포 관리** → 웹 앱 URL 의 복사 버튼
   (`https://script.google.com/macros/s/…/exec`)
2. **시크릿 40자** — 편집기에서 `setupSecret` 실행 → 실행 로그

> 직접 타이핑하지 마십시오. 40자 중 한 글자만 틀려도 인증 실패이고, 눈으로는 못 찾습니다.

## 단축어 A — "할 일 추가"

단축어 앱 → 우측 상단 **+** → 동작 네 개를 순서대로 넣습니다.

### 동작 ① 입력 요청 — 시리가 뭐라고 물을지 여기서 정한다

검색창에 **입력** → **입력 요청**

| 옵션 | 값 |
|---|---|
| 입력 유형 | 텍스트 |
| **프롬프트** | **`추가할 할 일을 말씀하세요`** |
| 기본 응답 | 비움 |

**이 프롬프트가 시리가 실제로 말하는 문장입니다.** 여기를 비워 두면 iOS 가
`"텍스트가 어떻게 됩니까?"` 라는 기본 문구를 대신 씁니다 — 무엇을 말해야 하는지
알려 주지 않아서, 특히 운전 중이나 잠금화면에서 잠깐 멈칫하게 됩니다.

이후 동작에서 쓰는 변수 이름은 **`제공된 입력`** 입니다
(아래 설명에서 변수를 넣는 자리마다 이것을 쓰십시오).

> **텍스트 받아쓰기를 써도 됩니다.** 다만 그 동작에는 프롬프트 칸이 없어서 시리의
> 기본 문구를 바꿀 수 없습니다. 대신 단축어 앱에서 **손으로 눌러 실행할 때** 곧바로
> 받아쓰기 화면이 뜨는 장점이 있습니다(입력 요청은 키보드가 뜹니다).
> 시리로 부르는 것이 주 용도라면 **입력 요청**이 낫습니다.

### 동작 ② 텍스트 — 여기서 주소를 조립합니다

검색창에 **텍스트** → **텍스트**

빈 칸에 아래를 **한 줄로** 넣습니다. 줄바꿈이 들어가면 안 됩니다.

```
<웹앱URL>?secret=<40자>&action=debug&text=
```

- `<웹앱URL>` 자리에 복사해 둔 주소를 붙여넣습니다 (`/exec` 까지)
- `<40자>` 자리에 시크릿을 붙여넣습니다
- 물음표 하나, 앰퍼샌드 두 개 — 위치를 그대로 지키십시오
- **처음에는 `action=debug`** 로 둡니다. 동작을 확인한 뒤 `add` 로 바꿉니다

그리고 **맨 끝 `text=` 바로 뒤에** 커서를 두고, 키보드 위 변수 막대에서
**`제공된 입력`**(텍스트 받아쓰기를 쓰면 `받아쓰기한 텍스트`) 을 탭합니다.
파란 알약이 들어가야 합니다 — 글자로 치면 안 됩니다.

완성된 모습:

```
https://script.google.com/macros/s/AKfy…/exec?secret=dBTW…&action=debug&text=[제공된 입력]
```

### 동작 ②-b URL 인코딩 — 빼면 제목이 잘립니다

검색창에 **인코딩** → **`URL 인코딩`** (없으면 아래 대안 참고)

입력은 **`제공된 입력`** 으로 둡니다. 위치는 ① 과 ③ 사이입니다.

**왜 필요한가** — 주소에 공백이 그대로 들어가면 거기서 URL 이 끝난 것으로 처리됩니다.
`text=내일 오후 3시 배포 파이프라인 점검` 를 보내면 서버에는 **`내일` 만** 도착하고,
제목이 "내일" 인 기한 없는 태스크가 만들어집니다. 실제로 그렇게 겪었습니다.

그리고 ③ 의 URL 끝 `&text=` 뒤에 넣는 변수를 **`URL 인코딩된 텍스트`** 로 바꿔야 합니다.
기존 `제공된 입력` 알약을 지우고 새 변수를 넣으십시오.

> **`URL 인코딩` 동작이 없다면** — **`텍스트 대체`** 로 대신합니다.
> 찾을 내용에 **공백 한 칸**, 바꿀 내용에 **`%20`**, 대상은 `제공된 입력`.
> 한글은 단축어가 알아서 처리하므로 공백만 막으면 대개 충분합니다.

### 동작 ③ URL의 콘텐츠 가져오기

검색창에 **URL** → **URL의 콘텐츠 가져오기**

- **URL 칸**: 기존 값을 지우고 변수 막대에서 **`텍스트`** 를 선택합니다 (②의 결과)
- **▾** 를 눌러 옵션을 펼치고 **메소드**가 **`GET`** 인지 확인합니다 (기본값입니다)
- **본문 요청**은 건드리지 않습니다. 필드를 만들지 마십시오

### 동작 ④ 사전 값 가져오기

검색창에 **사전** → **사전 값 가져오기**

| 옵션 | 값 |
|---|---|
| 가져올 항목 | 값 |
| 키 | `speak` |
| 대상 | `URL의 콘텐츠` (자동) |

### 동작 ⑤ 텍스트 말하기

검색창에 **말하기** → **텍스트 말하기** — `사전 값` 이 자동으로 들어갑니다.
옵션에서 언어를 한국어로 두면 발음이 자연스럽습니다.

### 시험

우측 상단 **▶**. 입력 화면(또는 받아쓰기 화면)에서 아무 말이나 하십시오.

`action=debug` 이므로 진단 결과가 나옵니다. 스크립트 속성에 `DEBUG=1` 이 있으면
`match:true` 를 포함한 JSON 이, 없으면 "진단이 꺼져 있습니다" 가 나옵니다.
**둘 중 무엇이든 나오면 통신은 성공한 것입니다** — 인증 실패가 아니라는 게 핵심입니다.

확인했으면 ② 의 `action=debug` 를 **`action=add`** 로 바꾸십시오.

```
"내일 오후 3시 배포 파이프라인 점검 급한 걸로"
→ "내일 15시 00분에 우선순위 1로 배포 파이프라인 점검, 프로젝트에 추가했습니다."
```

### 이름 짓기

화면 위 이름을 눌러 **`할 일 추가`**. 이 이름이 시리 호출어입니다.
짧고 또렷한 이름이 인식이 잘 됩니다. 잘 안 되면 "태스크 추가" 로 바꿔 보십시오.

## 단축어 B — "오늘 할 일"

말할 내용을 받을 필요가 없으므로 동작 네 개면 됩니다.

1. **텍스트** — `<웹앱URL>?secret=<40자>&action=today`  (변수 없음, 끝)
2. **URL의 콘텐츠 가져오기** — URL 칸에 `텍스트` 변수, 메소드 GET
3. **사전 값 가져오기** — 키 `speak`
4. **텍스트 말하기**

이름: **`오늘 할 일`**

## 단축어 C — "타스크" (등록·질문을 한 번에)

A·B 는 하는 일이 정해져 있습니다 — A 는 등록만, B 는 오늘 목록만. 말한 내용을 보고
**서버가 알아서 판단하게** 하려면 `action` 을 **`chat`** 으로 바꾸면 됩니다.
같은 백엔드가 앱의 AI 어시스턴트에도 쓰는 경로라, 태스크 전체를 보고 답하고
필요하면 직접 만들고 고칩니다.

```
"시리야, 타스크"
  → "무엇을 할까요?"
  → "오늘 할 일 알려줘"        → 오늘 것만 골라 읽어 줍니다
  → "급한 일 뭐 있어"          → P1·지연된 것 위주로 읽어 줍니다
  → "내일 3시 배포 파이프라인 점검 추가" → 만들고 확인해 줍니다
  → "이번 주 뭐가 밀렸는지"     → 한두 문장으로 짚어 줍니다
```

**만드는 법** — 단축어 A 를 복제(길게 눌러 **복제**)한 뒤 두 곳만 고칩니다.

1. **동작 ① 입력 요청**의 프롬프트를 **`무엇을 할까요?`** 로
2. **동작 ② 텍스트**의 주소에서 `action=add` 를 **`action=chat&voice=1`** 로

```
<웹앱URL>?secret=<40자>&action=chat&voice=1&text=[URL 인코딩된 텍스트]
```

이름은 **`타스크`** 처럼 짧게 짓습니다.

### `voice=1` 이 하는 일

이 플래그가 없으면 **화면용 답**이 돌아옵니다 — 앱 어시스턴트는 분석을 물으면 근거를
인용하며 길게 답하도록 되어 있는데, 그걸 시리가 읽으면 한참 걸립니다.

`voice=1` 이면 서버가 프롬프트를 바꿉니다: 마크다운·목록기호 금지, 3문장 이내,
할 일 열거는 급한 것 다섯 개까지. 그래도 길면 문장 경계에서 자르고
"자세한 내용은 앱에서 확인하세요" 로 맺습니다.

### 대가 — 조금 느립니다

`action=add` 는 문장 하나만 파싱하지만, `chat` 은 **태스크 전체 스냅샷을 실어** 모델을
부르고 필요하면 도구를 호출합니다. 등록만 할 때는 A 가 빠릅니다.

권하는 조합:

| | 언제 |
|---|---|
| **"할 일 추가"** (`action=add`) | 등록만 할 때. 가장 빠릅니다 |
| **"타스크"** (`action=chat&voice=1`) | 물어볼 때, 또는 무엇을 시킬지 애매할 때 |

둘 다 두고 상황에 따라 부르는 편이 실전에서 낫습니다. 하나만 쓰시겠다면 "타스크" 쪽입니다.

## 시리가 가로챌 때 — 말을 두 번 하지 않게 만든다

증상: 단축어를 부른 뒤 내용을 말했는데 **시리가 자기 방식으로 답하거나 ChatGPT 로 넘어간다.**

원인은 **말하는 턴이 두 번**이라는 데 있습니다.

```
1턴  "시리야, 타스크"        → 단축어 실행, "무엇을 할까요?"
2턴  "오늘 할 일 알려줘"      → ★ 여기가 문제
```

2턴의 문장이 시리 내장 의도(미리 알림·일정·날씨)나 일반 질문처럼 들리면, 단축어가
받기 전에 시리 쪽이 먼저 낚아챕니다. 특히 **"할 일"** 은 시리가 *미리 알림* 으로 아는
말이라 충돌이 잦고, 나머지는 Apple Intelligence 가 ChatGPT 로 넘깁니다.

### 대책 1 — ChatGPT 로 자동으로 넘어가지 않게

**설정 → Apple Intelligence 및 Siri → ChatGPT → `ChatGPT 요청 확인` 켜기**

넘기기 전에 한 번 물어봅니다. 조용히 끌려가는 일이 없어집니다.
아예 안 쓰실 거면 같은 화면의 `ChatGPT` 토글을 끄면 됩니다.

### 대책 2 — 단축어 이름을 예약어와 겹치지 않게

**피할 이름**: `할 일`, `할 일 추가`, `미리 알림`, `일정`, `메모`, `태스크`(≈task 로 들림)

**나은 이름**: `타스크 비서`, `업무 비서`, `내 업무` — 두 어절이고 시리 내장 기능에
같은 이름이 없는 쪽이 인식률이 높습니다.

### 대책 3 — 자주 쓰는 질문은 **입력 없는 단축어**로 (가장 확실)

2턴이 없으면 가로챌 기회 자체가 없습니다. 질문을 **URL 에 박아 두고** 한 번만 부릅니다.

```
"시리야, 급한 일"   → (바로 답) "긴급 두 건입니다. 배포 파이프라인 점검와 …"
```

동작 여섯 개, 받아쓰기도 입력 요청도 없습니다.

| 순서 | 동작 | 값 |
|---|---|---|
| ① | **텍스트** | `급한 일 알려줘` ← 질문을 여기에 고정 |
| ② | **URL 인코딩** | 입력: ①의 `텍스트` |
| ③ | **텍스트** | `<웹앱URL>?secret=<40자>&action=chat&voice=1&text=[URL 인코딩된 텍스트]` |
| ④ | **URL의 콘텐츠 가져오기** | URL 칸에 ③의 `텍스트`, GET |
| ⑤ | **사전 값 가져오기** | 키 `speak` |
| ⑥ | **텍스트 말하기** | |

①의 문장만 바꿔 복제하면 원하는 만큼 만들 수 있습니다.

| 단축어 이름 | ①에 넣을 문장 |
|---|---|
| `급한 일` | `급한 일 알려줘` |
| `밀린 일` | `기한 지난 일 알려줘` |
| `오늘 일정` | `오늘 할 일 알려줘` |
| `이번 주 정리` | `이번 주 뭐가 밀렸는지 한 줄로 짚어줘` |

> 이름을 `오늘 할 일` 이 아니라 **`오늘 일정`** 으로 둔 이유가 대책 2 입니다.

### 정리 — 이렇게 나눠 두십시오

| 단축어 | 발화 턴 | 쓰임 |
|---|---|---|
| `급한 일` · `밀린 일` · `오늘 일정` | **1턴** | 매일 쓰는 질문. 가로채기 없음 |
| `할 일 추가` (`action=add`) | 2턴 | 등록 전용. 가장 빠름 |
| `타스크 비서` (`action=chat&voice=1`) | 2턴 | 그 밖의 자유로운 요청 |

2턴짜리는 어쩔 수 없이 가로채기 여지가 남습니다. **매일 쓰는 것부터 1턴으로 옮기면**
체감 혼란이 대부분 사라집니다.

## 안 될 때

| 증상 | 원인 | 조치 |
|---|---|---|
| `인증에 실패했습니다` | 시크릿이 서버에 도달하지 않았거나 다름 | 브라우저에서 `?action=debug&secret=…` 를 먼저 열어 `match` 확인. 브라우저에서 되면 ②의 URL 조립이 잘못된 것 |
| `{"ok":true,"service":...}` 를 읽음 | 쿼리가 URL 에 안 붙었다 | ②의 `?` 와 `&` 위치 확인. ③의 URL 칸이 `텍스트` 변수인지 확인 |
| **제목이 첫 단어만 들어감** (예: 제목 "내일", 기한 없음) | 공백에서 URL 이 잘렸다 | 동작 ②-b **URL 인코딩** 을 넣고, `&text=` 뒤 변수를 인코딩된 것으로 교체 |
| 우선순위·기한이 안 잡힘 | 대개 위와 같은 원인 (뒷부분이 잘림) | 위와 동일 |
| `진단이 꺼져 있습니다` | `DEBUG` 속성 없음 | 통신은 정상이라는 뜻. `action=add` 로 바꾸면 됩니다 |
| 아무 말도 안 함 | ④의 키 오타 | 정확히 `speak` |
| 시리가 **"텍스트가 어떻게 됩니까?"** 라고 물음 | 동작 ①의 프롬프트가 비어 있거나 `텍스트 받아쓰기` 를 쓰고 있음 | 동작 ①을 **입력 요청**으로 바꾸고 프롬프트에 `추가할 할 일을 말씀하세요` 입력 |
| 시리가 URL 을 말해 달라고 물음 | 동작 ②의 텍스트 칸이 **매번 물어보기**로 설정됨 | 그 칸을 눌러 실제 주소 문자열로 되돌리기 |
| `chat` 답변이 너무 길다 | `voice=1` 이 빠졌다 | 주소에 `&voice=1` 추가 |
| `chat` 이 응답이 없거나 느리다 | 스냅샷 + 모델 + 도구 왕복이라 몇 초 걸린다 | 등록만 할 때는 `action=add` 단축어를 쓰기 |
| 시리가 자기 방식으로 답하거나 ChatGPT 로 넘어감 | 두 번째 발화를 시리가 먼저 낚아챈다 | 위 "시리가 가로챌 때" 절 — 입력 없는 1턴 단축어로 옮기기 |
| HTML 을 받아옴 | 도메인 제한 배포 | 배포를 **모든 사용자**로 다시 만들기 |
| 코드를 고쳤는데 그대로 | 배포는 스냅샷 | 배포 관리 → 연필 → **버전: 새 버전** → 배포 (URL 유지) |

**진단이 끝나면 스크립트 속성에서 `DEBUG` 를 삭제하십시오.** 그러면 진단 경로가 닫힙니다.
